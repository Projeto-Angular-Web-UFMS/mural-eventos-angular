Angular · Mural de Eventos10
Templates

Controle de fluxo: @if, @for e @empty

@if (loading()) {
  <p>Carregando eventos…</p>
} @else if (loadError()) {
  <p>Não foi possível carregar.</p>
} @else {
  @for (event of filteredEvents();
       track event.id) {
    <app-event-card [event]="event" />
  } @empty {
    <p>Nenhum evento encontrado</p>
  }
}
  • track é obrigatório: diz ao Angular como reconhecer cada item e reaproveitar o DOM
  • @empty trata a lista vazia sem outro @if
  • Projetos antigos usam *ngIf e *ngFor — você vai encontrá-los, mas a sintaxe nova é a recomendada

Injeção de dependências · conceito central

O componente pede; o injetor entrega

@Injectable({ providedIn: 'root' })
export class EventService {
  private http = inject(HttpClient);
}

export class EventList {
  private service = inject(EventService);
}
  • Por que não new EventService()? O componente teria que saber criar o serviço e as dependências dele
  • Novidade da v22: @Service(), um atalho para serviços já registrados no root

Valores que avisam quando mudam

const search = signal('');
const category = signal('');

const filtered = computed(() =>
  events().filter((e) =>
    (!category() || e.categoria === category()) &&
    e.titulo.toLowerCase()
      .includes(search().toLowerCase())
  )
);

search.set('git');           // escrita
search.update((s) => s.trim()); // usa o atual
effect(() => console.log(search()));

HttpClient e Observables

Por que um Observable e não uma Promise?

app.config.ts

providers: [provideRouter(routes), provideHttpClient()]

Forma 1 — subscribe

this.service.list().subscribe({
  next: (e) => this.events.set(e),
  error: () => this.loadError.set(true),
});

Forma 2 — converter em signal

events = toSignal(this.service.list(),
  { initialValue: [] });

RxJS: biblioteca de fluxos assíncronos (map, filter, switchMap…) — usada pelo Angular por baixo.

Reactive Forms

O formulário é um objeto no TypeScript

form = new FormGroup({
  titulo: new FormControl('', [
    Validators.required, Validators.minLength(5)]),
  data: new FormControl('', [
    Validators.required, futureDateValidator]),
});

function futureDateValidator(c) {
  if (!c.value) return null;
  return c.value > today() ? null
                           : { pastDate: true };
}

Estados do controle

Reflexão

Observables ou Signals? Os dois, cada um no seu papel

Observable — fluxo no tempo

  • Requisições HTTP, eventos, WebSockets
  • Valores que chegam ao longo do tempo
  • Cancelar, combinar, repetir (RxJS)

Signal — estado atual

  • O que a tela mostra agora
  • Leitura síncrona no template: events()
  • Derivados com computed, sem gerenciar inscrições
Angular · Mural de Eventos24
Reflexão · postura crítica

O custo das convenções

O que custa

  • Mais arquivos e mais código que React e Vue para o mesmo Mural
  • Curva de aprendizado alta: TypeScript, DI, RxJS e decorators desde o primeiro dia
  • Mudanças rápidas: standalone, Signals, @if, zoneless, @Service — muito material antigo na internet
  • Menos liberdade: o framework decide a estrutura por você

Quando compensa

  • Equipes grandes: todo mundo escreve código parecido
  • Projetos longos: quem chega daqui a 3 anos encontra a mesma estrutura
  • Sistemas corporativos: formulários complexos, muitas telas, testes
  • Atualizações guiadas: ng update migra o código entre versões
Para um protótipo de fim de semana, o Angular é pesado. Para um sistema que 20 pessoas vão manter por anos, as convenções se pagam.
